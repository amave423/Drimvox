# Контекст проекта (рабочее имя — выбирается, см. «Открытые вопросы»)

> Источник: опрос владельца 2026-10-11 (8 раундов). Этот файл — главный источник правды
> о том, ЧТО строим и ПОЧЕМУ. Любой агент (человек или ИИ) читает его перед работой.

## 1. Суть в одном абзаце

Десктопное приложение для Windows, где команда ИИ-агентов разрабатывает код под присмотром
человека. Агенты работают на **любых нейросетях любых провайдеров** (по ключам пользователя,
по подписке через CLI или локально). Главный агент (оркестратор) делит большую цель на
подзадачи и раздаёт их агентам на более дешёвых моделях. Каждый агент работает в своей копии проекта
(git worktree). «Готово» подтверждается не словами модели, а запуском тестов, сборки и
визуальной проверкой. Последнее слово — за человеком: построчный diff → «Принять» / «Вернуть».
Дополнительно приложение служит AI-хабом: чат с любой моделью и генерация картинок.

Ориентиры: процесс из видео AshyGray «Почему ты вайбкодишь неправильно» (опрос → план →
тесты до кода → оркестратор → изоляция) и продукт VibeForge (vibe-forge.ru).

## 2. Для кого и как распространяется

- Open-source на GitHub. Каждый ставит себе сам и работает со **своими** ключами.
- **Общего сервера нет.** Приложение однопользовательское: без аккаунтов, подписок и биллинга.
- Знакомые получают ссылку на репозиторий и устанавливают приложение сами.

## 3. Платформы и этапность

| Этап | Платформа | Как |
|---|---|---|
| v1 | **Windows, десктоп** | Electron-окно + локальный Node-бэкенд |
| позже | **Сервер на Ubuntu** (ноутбук владельца) | Тот же бэкенд без окна + тот же веб-интерфейс по IP. Все данные хранятся на сервере. Доступ из интернета через **Tailscale**, вход по паролю/токену |

Архитектура закладывается под оба режима **с первого дня** (см. §9), но серверный режим
собирается и тестируется только после стабильного десктопа.

## 4. Уроки Orqen Studio — что НЕ повторяем

Orqen: ~37k строк и 378 коммитов, из них подавляющее большинство — `fix(verify)`, `fix(repair)`, `fix(intake)`.
Владелец назвал все четыре боли:

1. **Постоянные баги.** Причины: файлы на 1–2.7k строк (`runner.py` — 2771), смешение
   Python + Node + Rust, отсутствие тестов на ядро, фиксы поверх фиксов.
2. **Агенты «врали готово».** Проверка была эвристиками внутри промптов, а не
   жёстким гейтом в коде.
3. **Слишком много всего.** В одном продукте были OpenVSCode, терминал, установщики, скачивание
   локальных моделей, Tauri, серверная версия и магазин агентов.
4. **Сложно и медленно.** Тяжёлая установка, долгие прогоны, циклы визуальной проверки.

**Правила-противоядия:**
- Один язык (TypeScript) во всём проекте.
- Файл > ~400 строк — сигнал к разбиению. Модуль = одна ответственность.
- Ядро (провайдеры, агентный цикл, гейты проверки) покрыто тестами **до** UI.
- «Готово» — это состояние, которое вычисляет код (exit code тестов/сборки), а не фраза модели.
- У каждого цикла есть жёсткий лимит итераций и денег. Бесконечных repair-циклов нет.
- Фичи вне текущего этапа не делаем, даже «по пути».

## 5. Нейросети и провайдеры

**Ключи владельца** (хранятся только в зашифрованном хранилище приложения / `.env`, никогда в git):
OpenRouter, DeepSeek, fal.ai, NVIDIA NIM.

Поддерживаемые типы подключений:
- **OpenAI-совместимый** (одна универсальная форма: base URL + ключ) — покрывает
  OpenRouter, DeepSeek, NVIDIA NIM и любой похожий сервис.
- **Нативные API:** Anthropic, OpenAI, Google Gemini, xAI — этап M7. До него эти модели доступны через OpenRouter.
- **Локальные:** Ollama / LM Studio — только подключение к уже запущенному серверу.
  Скачивания и запуска моделей внутри приложения нет.
- **CLI-подписки:** Claude Code, Codex CLI, Gemini CLI как исполнители-агенты
  (работа по подписке пользователя).
- **Медиа:** fal.ai — картинки в чате и ассеты для проектов (иконки, баннеры, иллюстрации).
  Видео и аудио пока не нужны.

**Выбор модели:** вручную для каждой роли. Приложение подсказывает цену, размер контекста,
поддержку tool-calling и vision.

**Деньги:** счётчик токенов и $ по агенту, сессии и провайдеру; балансы провайдеров
там, где API их отдаёт (OpenRouter, DeepSeek). Бюджетные лимиты не требовались, но нужен
предохранитель «стоп на тратах сверх порога» (см. §7).

## 6. Агенты

- **Шаблоны ролей + редактирование:** планировщик/оркестратор, кодер, тестировщик,
  ревьюер, дизайнер (с fal.ai). У каждой роли редактируются промпт, модель и набор
  инструментов. Можно создавать свои роли. Визуальный граф — не в v1.
- **Режимы v1:** **Solo** (один агент ведёт задачу целиком) и **Оркестратор**
  (главный агент делит цель, назначает подзадачи агентам и моделям, сливает результат).
  Swarm и Fusion — не нужны.
- **Инструменты агентов:** файлы и команды (в своей копии проекта), веб-поиск и чтение
  страниц, браузер Playwright для проверки собранного приложения, MCP-серверы и скиллы.

## 7. Рабочий процесс задачи (пайплайн)

```
Опрос → Спека/план → [OK владельца] → Тесты (красные) → Код (до зелёных)
     → Проверка (тесты + сборка + визуальная) → Ревью diff владельцем → Слияние
```

- По умолчанию проходим весь путь; любой шаг можно пропустить кнопкой («без опроса»,
  «без тестов»).
- **Опрос** — карточки: вопрос, 2–4 варианта, «свой ответ», рекомендуемый вариант помечен.
- **План оркестратора** показывается со списком подзадач, агентов и моделей. Работа стартует
  только после «ОК». План можно поправить.
- **Проверка «готово»:** тесты + сборка (по exit code) + визуальная проверка (скриншот через
  Playwright → vision-модель). Визуальная проверка ограничена N попытками. При провале задача
  эскалируется, в цикл не уходит.
- **Застрял** (N неудачных попыток) → эскалация к оркестратору или более сильной модели →
  если снова провал — честный отчёт владельцу: ошибка, что пробовали, варианты.
- **Автономность:** внутри своей копии агент делает всё сам. Останавливается и спрашивает
  перед действием вне копии, удалением вне копии, `git push`, глобальной установкой пакетов
  и тратами сверх порога.
- **Изоляция:** каждый агент получает свой git worktree и свою ветку. Основная ветка не меняется до
  «Принять».
- **Ревью:** построчный diff, комментарий к строке → «Вернуть на доработку» или «Принять» (merge).

## 8. Интерфейс

- **Панели v1:** проекты/сессии, чат и ход работы, файлы + diff (Monaco, только
  просмотр и мелкие правки). Встроенного VS Code, терминала, превью сайта и
  GitHub-панели в v1 **нет**.
- **Сессии:** несколько задач параллельно; память проекта (`AGENTS.md` + спеки в проекте,
  агенты читают и обновляют); уведомления Windows, когда агент закончил или ждёт ответа
  (Telegram — позже); история действий агента и откат сессии целиком.
- **Языки:** русский + английский (i18n с первого дня).
- **Темы:** тёмная + светлая, по умолчанию как в системе. Обе темы задаются одними
  токенами, без отдельного файла «оверрайдов».
- **Стиль:** смесь «строгий pro-инструмент» + «тёплый бумажный» + «командный центр».
  Компоновка и финальный стиль выбираются по макетам (`design/variants.html`).

## 9. Технологии (решение принято за владельца — «решай сам»)

| Слой | Выбор | Почему |
|---|---|---|
| Язык | TypeScript везде | Один язык, один рантайм — нет багов на стыке Python/Node/Rust |
| Десктоп | Electron; ядро — в отдельном `utilityProcess` | Node внутри, без Rust. Тяжёлая работа агентов не тормозит окно |
| UI | React + Vite + Tailwind/CSS-токены | Тот же бандл для сервера в браузере |
| Бэкенд-ядро | Node + Hono (+ типизированный RPC-клиент), отдельный пакет `core` | Один и тот же код в Electron и на Ubuntu. Типы API общие для UI и ядра — меньше ошибок на стыке |
| БД | SQLite через встроенный `node:sqlite` + свои миграции | Нет нативных модулей и пересборки под Electron. Проверено: Electron 44 / Node 24.21 |
| LLM-слой | Vercel AI SDK (+ openai-compatible, anthropic, google, xai, ollama) | Стриминг, tool-calling и usage единообразно для всех провайдеров |
| Медиа | `@fal-ai/client` | Официальный клиент |
| Инструменты | `@modelcontextprotocol/sdk`, Playwright | MCP и браузерная проверка |
| Секреты | Electron `safeStorage` (десктоп) / файл + мастер-пароль (сервер) | Ключи не лежат открытым текстом |
| Тесты | Vitest (ядро), Playwright (e2e UI) | — |

Структура монорепо (черновик):
```
apps/desktop   — Electron main + preload (тонкий)
apps/web       — React UI (один для десктопа и сервера)
packages/core  — бэкенд: провайдеры, агенты, пайплайн, worktree, БД, API
packages/shared — типы и схемы (zod), общие для UI и core
```
