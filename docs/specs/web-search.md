# Спека: поиск в интернете — ключ сервиса и проверки, которые проходит человек

## Зачем

Бесплатный поиск (DuckDuckGo) раз за разом блокировал запросы, а сайты отвечали скрытому браузеру агента капчей.
Пользователь выбрал: поиск по ключу сервиса и капчу, которую проходит он сам.

## Поиск

- Настройки → «Интернет» → «Поиск в интернете»: бесплатный (по умолчанию), Tavily или Brave Search с ключом.
- Ключ хранится зашифрованным в `settings` (ключ `search`) и наружу не отдаётся: API отвечает
  `{ service, hasKey }`. «Проверить» делает один поиск: работает / ключ не принят / тариф кончился.
- С ключом `web_search` у всех (чаты, проекты, агенты) идёт через сервис (`internet/search-service.ts`);
  ответы приводятся к тем же «заголовок, адрес, отрывок». Без ключа — бесплатный поиск, как раньше.

## Прокси только для заблокированных сайтов

Попросили: часть источников недоступна из России, но и через прокси пускают не все российские сайты. Прокси из
настроек используется только для сайтов из списка «Сайты через прокси» (Настройки → Прокси; сначала — известные
закрытые: instagram.com, facebook.com, x.com, twitter.com, linkedin.com, discord.com, rutracker.org, medium.com).
Чтение страниц ядром (`open_page`) и встроенный браузер на компьютере (PAC-скрипт сессии) открывают остальное
напрямую. Сайт, который не открылся напрямую из-за обрыва соединения (сброс, таймаут, нет имени), пробуется через
прокси и, если открылся, добавляется в список сам; ответ сайта вроде 404 блокировкой не считается. Пароль прокси
браузер получает из адреса в настройках. На сервере браузер пока ходит напрямую.

## Проверки, которые проходит человек

- Инструмент `open_for_user(url, reason)` — только в десктопе. Агент вызывает его, когда сайт просит доказать, что
  он человек (капча, проверка от ботов), или нужен вход пользователя.
- Drimvox открывает видимое окно в той же сессии браузера, в которой агент читает страницы (`browse_page`).
  Заголовок окна — что сделать. Пользователь проходит проверку и закрывает окно; агент получает текст страницы и
  дальше читает сайт с теми же cookie.
- Сам агент проверки не обходит и не решает (`FAIR_USE_HINT`).

## Тесты

- Ядро: ключ не хранится открытым и не возвращается; проверка ключа (работает, не принят); поиск через Tavily и Brave
  с разбором ответа; чат с интернетом ищет через сервис; `open_for_user` показывает страницу и отдаёт модели её текст.
- e2e: раздел «Интернет» с поиском и «?»-подсказкой.
