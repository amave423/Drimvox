# Спека: Solo-агент

Решения из опроса 2026-10-12. Общий контекст — `docs/CONTEXT.md`, дизайн — `docs/DESIGN.md`.

## Что получает пользователь

Выбирает папку проекта, пишет задачу, выбирает модель. Агент работает в **отдельной копии**
проекта (git worktree на своей ветке). Рабочая папка пользователя не меняется, пока он не нажмёт
«Принять». Пока агент работает, видна лента действий. Когда агент закончил, открывается экран
«Корректура»: построчный diff, замечания к строкам, кнопки «Вернуть на доработку», «Принять»,
«Отказаться».

## Проекты

- Подходит любая папка. Если в ней нет git, Artel предлагает сделать первый коммит
  (`git init` + коммит всех файлов, автор — git-профиль пользователя) и делает его только после согласия.
- Пустая папка тоже подходит: это новый проект.
- Если на компьютере нет git или не настроены `user.name` и `user.email`, Artel объясняет, что сделать.

## Копия проекта

- `git worktree add -b artel/<id> <данные Artel>/worktrees/<id> HEAD` — отдельная папка и ветка.
- Запоминается базовый коммит: от него считается diff.
- После «Принять» или «Отказаться» копия и ветка удаляются.

## Агент

- Цикл модели с инструментами (AI SDK `streamText` + tools):
  - `list_files`, `read_file`, `search` — чтение;
  - `write_file`, `edit_file` — запись (замена уникального фрагмента);
  - `run_command` — команда в PowerShell (Windows) или sh, рабочая папка = копия, таймаут, вывод обрезается;
  - `finish(summary, commit_message)` — агент сам говорит, что закончил, и предлагает сообщение коммита.
- Любой путь вне копии — ошибка инструмента, а не действие.
- **Спрашивает перед**: `git push`, глобальной установкой пакетов, удалением или изменением путей
  вне копии, выключением/форматированием системы. Агент ждёт ответа на карточке «Разрешить / Запретить».
- **Лимиты**: бюджет на задачу (по умолчанию $0.50, меняется в настройках; бесплатные модели не тратят),
  максимум 60 шагов. Упёрся — останавливается со статусом «ждёт тебя» и объяснением; можно продолжить.
- Работа идёт в ядре и не зависит от открытого окна: можно переключиться на другой экран.
- После перезапуска приложения незаконченная задача помечается «остановлена»; копия и правки сохраняются.

## Статусы задачи

`running` → `review` (есть правки) · `done_empty` (правок нет) · `waiting` (вопрос, лимит) ·
`failed` (ошибка провайдера) · `stopped` (Стоп или перезапуск) → `accepted` / `discarded`.

## Лента действий

Одна строка на действие: «Читает src/app.ts», «Правит 2 места в api.ts», «Запустил npm test → код 1».
По клику раскрываются детали: вывод команды, фрагмент файла. Текст модели между действиями — заметками.

## Ревью

- Diff базового коммита и копии, включая новые и удалённые файлы.
- Удалённое — красным карандашом (зачёркнуто), добавленное — синими чернилами.
- Замечание к строке → на полях. «Вернуть на доработку» отправляет агенту все замечания и общий
  комментарий; агент продолжает в той же копии.
- «Принять» = один коммит в текущую ветку проекта (`git merge --squash` + коммит с сообщением агента,
  которое можно поправить). Если в рабочей папке есть незакоммиченные правки тех же файлов — понятная ошибка,
  ничего не теряется.

## Готово, когда

- Все пункты выше покрыты тестами ядра на настоящем git-репозитории и фейковой модели с вызовами инструментов.
- Сквозной тест в окне: проект → задача → лента → ревью → замечание → доработка → принять → коммит в репозитории.
