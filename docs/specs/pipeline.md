# Спека: порядок работы агента «опрос → спека → тесты → код → проверка»

Решения из опросов 2026-10-11 и 2026-10-12. Продолжает `docs/specs/solo-agent.md`.

## Зачем

Агенту нельзя верить на слово. «Готово» считается только тогда, когда Artel сам запустил проверки
проекта и они прошли. Опрос и спека нужны, чтобы агент понял задачу до того, как начнёт писать код.

## Шаги задачи

```
опрос → спека и план → [ОК владельца] → тесты (должны упасть) → код (до зелёных) → проверка → ревью
```

При запуске задачи три переключателя, все включены по умолчанию:
- **Опрос** — без него агент сразу пишет спеку.
- **Подтверждать спеку** — без него спека принимается автоматически, но остаётся видна.
- **Тесты до кода** — без него агент сразу пишет код; проверки после кода остаются в любом случае.

## Опрос

- Агент смотрит проект (только чтение) и задаёт до 6 вопросов одним заходом.
- Каждый вопрос — карточка: вопрос, 2–4 варианта с пояснением, рекомендуемый помечен, есть «Свой ответ».
- Задача ждёт ответа («ждёт тебя»). Можно ответить на всё или нажать «Пропустить опрос».
- Если вопросов нет, агент сразу переходит к спеке.

## Спека и план

- Агент (только чтение) пишет спеку в Markdown: что должно получиться, что вне задачи, как проверить.
- Предлагает **команды проверки**, найденные в проекте (`npm test`, `npm run build`, `pytest`…), и план шагов.
- Если в проекте нет тестов, план начинается с пункта «поставить минимальный тест-раннер»
  (`node --test`, `pytest`, `vitest` — что подходит проекту).
- Владелец видит спеку, команды и план. Может поправить спеку и команды прямо там, нажать «Начать работу»
  или «Переписать спеку» с комментарием.

## Тесты до кода

- Агент пишет тесты по спеке (и ставит раннер, если его нет), затем вызывает `finish`.
- Artel сам запускает команды проверки. Ожидание: **красные** (новое поведение ещё не сделано).
- Если всё уже зелёное — агенту один раз говорится, что тесты не проверяют новое поведение; после
  повтора идём дальше с пометкой в ленте.

## Код и проверка

- Агент пишет код и вызывает `finish`. Artel запускает команды проверки.
- **Все зелёные** → ревью. Агентские слова «готово» без зелёных проверок ничего не значат.
- **Красные** → вывод упавших команд уходит агенту, следующая попытка.
- **3 красных прогона подряд** → эскалация: задача продолжается на «сильной модели» из настроек,
  счётчик попыток обнуляется. Эскалация одна на задачу.
- Если сильная модель не выбрана или тоже не справилась за 3 прогона → «ждёт тебя» с честным отчётом:
  какие проверки падают и с каким выводом. Можно «Продолжить» (ещё 3 попытки), «Принять как есть» или отказаться.
- Если команд проверки нет (владелец убрал все) — ревью без проверок, с явной пометкой.

## Лента

Новые строки: вопросы и ответы, спека, смена шага («Пишет тесты», «Пишет код»), каждая проверка
(«Проверка: npm test → код 1», вывод по клику), эскалация на другую модель.

## Готово, когда

- Ядро: тесты на каждый переход шага, на красный/зелёный гейт, на 3 попытки и эскалацию, на «застрял»,
  на пропуск шагов — на настоящем git-репозитории и фейковой модели.
- Окно: сквозной тест «опрос → спека → правка команды → тесты красные → код зелёный → ревью».
- Живая проверка на настоящей модели проходит весь путь на маленькой задаче.
