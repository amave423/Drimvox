# Подписки через CLIProxyAPI

Попросили: бесплатный доступ к моделям через свои аккаунты (Claude, ChatGPT, Google, Kimi, Grok) — отдельной
вкладкой в «Локальных моделях», со скачиванием и удалением как у других движков, переключателями «сервер вкл/выкл»
и «выключать при закрытии», лимитами по аккаунтам с временем сброса, как на сайтах самих сервисов.

## Как это устроено на самом деле

- [CLIProxyAPI](https://github.com/router-for-me/CLIProxyAPI) (MIT) — одна программа, которая входит в аккаунты по
  OAuth и отдаёт их модели как обычный OpenAI-совместимый API на `127.0.0.1`. Для Drimvox это провайдер
  «CLIProxyAPI» в «Ключах и моделях»: его модели — в выборе модели, в чате и в проектах.
- Это не «бесплатно вообще»: тратятся лимиты аккаунтов — бесплатного тарифа Google или купленной подписки Claude
  Pro/Max, ChatGPT Plus/Pro. Сервисы так пользоваться подписками не разрешают — аккаунт могут ограничить; на
  вкладке это сказано прямо.
- Лимиты — у аккаунтов, а не у моделей: у Claude и Codex окно 5 часов и неделя (у Claude бывает ещё неделя
  отдельной модели), у Antigravity — квота на каждую модель. Сам CLIProxyAPI их не знает: Drimvox спрашивает каждый
  сервис от имени аккаунта через `/v0/management/api-call` (CLIProxyAPI подставляет токен аккаунта вместо
  `$TOKEN$`): Claude — `api.anthropic.com/api/oauth/usage`, Codex — `chatgpt.com/backend-api/wham/usage`,
  Antigravity — `cloudcode-pa.googleapis.com/v1internal:fetchAvailableModels`. Kimi и Grok лимиты не сообщают.

## Что видно

- Вкладка «Подписки» в «Локальных моделях». Нет программы — «Скачать» (≈25 МБ, с прогрессом).
- Скачана: «Сервер включён — 127.0.0.1:порт» (переключатель), «Выключать сервер при закрытии Drimvox» (по
  умолчанию да; выключено — сервер живёт дальше для Claude Code и Codex, Drimvox подхватывает его при запуске),
  версия, «Удалить CLIProxyAPI» (с подтверждением, вместе со входами).
- Аккаунты: список (сервис, почта, состояние, «Удалить») и кнопки «Войти: Claude, ChatGPT (Codex), Google
  (Antigravity), Kimi, Grok». Вход открывает страницу сервиса в браузере; Drimvox раз в 2 секунды спрашивает, готово
  ли. У Kimi и Grok — код для страницы. На сервере страница входа не может вернуться на `localhost`: браузер покажет
  ошибку на адресе `localhost…?code=…` — его вставляют в поле, Drimvox отдаёт его CLIProxyAPI (`/oauth-callback`).
- Лимиты: у каждого аккаунта полоски «использовано N%» и «сброс через …», обновляются раз в минуту.

## Устройство

- `packages/core/src/local/cliproxy/install.ts` — закреплённый выпуск (8.0.48) с SHA-256 каждого архива из его
  `checksums.txt`: zip (Windows) или tar.gz (Linux, macOS), распаковка в памяти, полураспакованное не считается.
- `service.ts` — настройки в `settings` (`cliproxy`: порт, ключи управления и клиента — зашифрованы, «выключать при
  закрытии», «включён», pid оставленного сервера, id провайдера). `config.yaml` в папке данных `cliproxy/`:
  `server.host 127.0.0.1`, свободный порт (8317, если свободен), `management.secret-key`, `allow-remote: false`,
  `disable-control-panel: true`, `access.api-keys` — ключ клиента, `oauth.auth-dir` — `cliproxy/auths`. Сервер,
  оставленный работать, — отдельный процесс (`detached`); при запуске Drimvox сначала проверяет, отвечает ли он.
- API: `GET/PATCH/DELETE /api/subscriptions`, `POST /install`, `GET /accounts`, `DELETE /accounts/:name`,
  `POST /login`, `GET /login/:state`, `POST /login/callback`, `GET /limits`.
