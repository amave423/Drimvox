# Спека: локальные модели через Ollama

Решения из опроса 2026-10-13. Цель: скачать и запустить модель на своём компьютере, не выходя из Drimvox.
Локальные модели нужны в основном для обычного чата, иногда для одиночного агента на простых задачах.

## Движок — только Ollama

- Модели качает и запускает Ollama. Она умеет и свой каталог, и GGUF-модели с Hugging Face
  (`hf.co/автор/репозиторий:вариант`), так что второй движок не нужен.
- Ollama не установлена: на Windows и macOS лист предлагает «Скачать движок · размер». Drimvox качает Ollama как
  программу, без установщика (попросили в 1.9.2: официальный установщик ставил отдельное приложение со значком в трее и
  входом): архив со страницы релизов GitHub (`ollama-windows-amd64.zip` 1,5 ГБ, `-arm64.zip`, `ollama-darwin.tgz`
  180 МБ), прямо на диск, сверка с `sha256sum.txt` рядом, распаковка системным `tar` (на Windows — `System32	ar.exe`
  по полному пути: встроенный git ставит GNU tar первым в PATH) в `<данные>/engines/ollama`. Своя Ollama человека,
  если она есть, — первая; скачанная Drimvox — вместо неё. Модели обеих лежат там, где их держит Ollama по умолчанию
  (`OLLAMA_MODELS` или `~/.ollama/models`). На Linux — команда официального скрипта (сервер ставит Ollama службой).
  Галочка «Установить Ollama» в установщике Drimvox делает то же при первом запуске.
- Ollama установлена, но не запущена: Drimvox запускает `ollama serve` в фоне сам, когда она нужна
  (открыт лист, идёт скачивание, чат или агент на локальной модели), и пишет об этом на листе.
- Запущенную им Ollama Drimvox **убирает из фона**, когда она не нужна: 10 минут без запросов, ничего не
  скачивается и в памяти нет загруженных моделей. Ollama, которую запустил сам человек (приложение в трее,
  служба на сервере), Drimvox не трогает.
- Запуская Ollama сам, Drimvox задаёт ей окно контекста: 16 тысяч токенов, а при видеокарте или общей памяти
  от 24 ГБ — 32 тысячи. По умолчанию у Ollama окно маленькое, и модель «забывает» длинный разговор.
- Агент и память чата считают на это окно, а не на окно модели из её описания (`ollama-details.ts`): Ollama молча
  обрезает начало запроса длиннее своего окна, а через `/v1` его не задать. У Ollama, запущенной самим человеком, — её
  окно по умолчанию, 4 096 токенов (сказано в видео про агентов: на видеокартах меньше 24 ГБ — 4 тысячи).
- Адрес — как у пресета Ollama (`127.0.0.1:11434`). Провайдер Ollama с другим адресом (Ollama на другой
  машине) Drimvox не запускает и не останавливает.

## Под это железо

- Drimvox смотрит память и видеокарту: объём оперативной памяти; видеопамять NVIDIA (`nvidia-smi`), на Windows
  у прочих видеокарт — из реестра драйвера, на Linux у AMD — из `/sys`; у Mac на Apple Silicon память общая.
- Нужно памяти ≈ размер файла × 1,15 + 1 ГБ на контекст.
  - «Быстро» — помещается в видеопамять.
  - «Медленно» — помещается только вместе с оперативной памятью (берётся 75 % от неё): часть работы идёт
    на процессоре.
  - Не помещается — модели **нет в списке**.
- Совет из вариантов сжатия одной модели: лучший быстрый от 4 бит (не выше Q8_0); если такого нет — самый
  маленький от 4 бит, пусть и медленный: двухбитный вариант быстр, но заметно глупее; если и такого нет — лучший
  быстрый от 3 бит; иначе самый маленький. Совет отмечен, остальные варианты видны.

## Каталог

- Сверху — **подборка**: несколько проверенных моделей из каталога Ollama разного размера, для чата и простых
  задач, с короткой подписью на двух языках, что модель умеет (чат, код, картинки). Размеры берутся из реестра
  Ollama в момент показа, не зашиты в код. Модель, тег которой пропал из реестра, просто не показывается.
- Ниже — **поиск по Hugging Face** среди GGUF-моделей, по скачиваниям. Репозиторий, у которого даже самый
  сжатый вариант не поместится, в выдачу не попадает (оценка по числу параметров). Открытый репозиторий
  показывает варианты сжатия с размерами и советом; многофайловые варианты, `mmproj` и `imatrix` не показываются.
- Скачивание идёт с прогрессом (сколько из скольких, скорость), его можно отменить. Скачанные модели видны
  списком с размером, их можно удалить.
- Скачанный с HF файл для Ollama на этом компьютере Drimvox **перекладывает** в её папку `blobs` (`sha256-<hex>`):
  мгновенно и без второй копии на диске (замечено: две модели заняли 45 ГБ дважды). Если та Ollama файла там не видит
  (свой `OLLAMA_MODELS` у службы, другой диск), файл возвращается и передаётся (`POST /api/blobs`) потоком с обратным давлением (`uploadFile`), затем
  делает из него модель (`/api/create`). Замечено вживую в 1.9.0: передача через `fetch` читала весь файл в память
  ядра (16,5 ГБ памяти на модель в 16,5 ГБ), модель в 29 ГБ роняла ядро — чат писал ошибку ядра, а модель так и не
  появлялась в списке. Скачанный файл остаётся до успешного создания модели: повторное «Скачать» идёт сразу к передаче.
- Имя модели в Ollama — `hf.co/<репозиторий>:<вариант>`, но ни одна часть не длиннее 80 знаков (`ollamaName`): у
  репозитория с именем в 85 знаков Ollama отказала «invalid model name» уже после скачивания. Длинная часть обрезается;
  Hugging Face по-прежнему спрашивается по полному имени.

## Чат и агент

- **Мышление** (попросили в 1.9.2: у локальных моделей переключателя не было, и думающая модель всегда думала по
  максимуму). У Ollama и LM Studio в чате и в проекте тот же переключатель «Мышление»: уровень уходит как
  `reasoning_effort` (выкл — `none`), Ollama передаёт его в шаблон модели. Замерено на Qwen 3.8 27B: без уровня
  870 знаков размышлений и 343 токена, «низкое» — 109 токенов, «выкл» — 4. Шаблон, который такого уровня не знает
  (та же модель: «high» нет, есть «xhigh»), или модель, которая не думает, отвечают ошибкой — запрос тут же
  повторяется без уровня (`withoutEffort` в `providers/model.ts`), и модель думает по-своему.

- После первого скачивания Drimvox сам добавляет провайдера Ollama, если его нет: модели сразу видны
  в выборе модели чата и задачи. Если модели в Ollama уже есть (скачаны раньше, своей командой или на новом сервере),
  провайдер добавляется сам — при запуске Drimvox, если Ollama уже работает, и при открытии листа (было: на сервере
  чат просил «подключить нейросеть», и это читалось как «нужен ключ»).
- Любой запрос к Ollama по адресу Drimvox (список моделей, чат, агент) сначала будит её, если нужно,
  и продлевает ей жизнь.
- Подсказка на листе: для чата хватит модели поменьше, для задач агента нужна модель, умеющая вызывать
  инструменты, и чем больше, тем лучше.

## Подписки

Вкладки «Подписки» с CLIProxyAPI больше нет (попросили: всё это уже умеет само приложение). При запуске Drimvox один раз
убирает то, что она оставила: своего провайдера, программу и настройку. Сервер, оставленный работать, по старому номеру
процесса не останавливается — номер мог достаться другой программе.

## Сервер

То же ядро: на Ubuntu Ollama обычно работает службой — тогда Drimvox её только использует.

## Проверка

- Юнит-тесты: оценка «быстро / медленно / не поместится», совет варианта, разбор вывода `nvidia-smi` и реестра,
  разбор файлов репозитория HF, подборка с размерами из реестра (поддельный реестр), поиск HF (поддельный HF),
  запуск и остановка поддельной Ollama по простою, чужая Ollama не останавливается, скачивание с прогрессом
  и отменой, провайдер после скачивания, чат будит Ollama.
- e2e на настоящем окне: лист «Локальные модели» с поддельной Ollama — подборка без невлезающих моделей,
  скачивание с прогрессом, модель появилась в чате и отвечает.
- Живая проверка: настоящая Ollama на этом компьютере (RTX 3080 10 ГБ, 32 ГБ), маленькая модель из подборки,
  чат на ней, Ollama уходит из фона после простоя.

## Hugging Face files (Drimvox downloads them)
- Seen from Russia: huggingface.co answers, but the file server it redirects to (us.aws.cdn.hf.co) does not, so
  Ollama's own `pull hf.co/...` fails with a TLS timeout. hf-mirror.com only redirects back to huggingface.co.
- Drimvox downloads `hf.co/<repo>:<quant>` itself: the file and its sha256 from huggingface.co's API, the bytes straight
  and, when that fails, through the proxy from the settings. Range requests resume after a pause; the partial file
  waits in the data folder's `downloads` and is deleted on cancel.
- The finished file is checked against the sha256, given to Ollama as a blob (`/api/blobs`) and made a model with
  `/api/create`; Ollama reads the chat template from the GGUF. Vision projectors are not fetched.
- Without a proxy and with the file server closed, the error says to set one.

## Без ограничений по времени

Попросили: локальные модели и так медленные. Модель Ollama или LM Studio не обрывается за молчание (в чате, задаче
агента и проекте) и не останавливается по часам работы проекта; её останавливает только «Стоп» (`isLocal` в `budget.ts`).
