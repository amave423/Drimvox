# Спека: git в проекте — правила для агента

## Зачем

Попросили: в проекте был только «коммит», и непонятно, что и куда уходит. Из макетов (`design/project-github.html`,
`design/project-git-rules.html`) выбран вариант «Правила для агента» без ручных коммитов: один раз сказать, как работать
с git, дальше агент делает это сам, а пользователь принимает или отклоняет.

## Что видно

Во вкладке «Проект» — карточка «Git: как работает агент»:

- **Куда пишет:** своя ветка на задачу (`drimvox/task-ММДД-ЧЧММ`, по умолчанию), одна рабочая ветка (`drimvox/work`),
  в текущую ветку, прямо в main (только с «Можно писать прямо в main», иначе — своя ветка).
- **Когда коммитит:** после каждого пункта плана (по умолчанию), один коммит в конце задачи, логичными частями — сам
  решает, не коммитит (git остаётся пользователю, как было).
- **Сообщения:** как в истории проекта (по умолчанию: агенту показываются последние 8 сообщений), коротко по-английски,
  коротко по-русски, Conventional Commits.
- Переключатели: «Отправлять ветку на GitHub», «Открывать pull request в конце» (оба включены), «Можно писать прямо в
  main» (выключен). Без репозитория на GitHub или без входа в GitHub — строка, что ветка уйдёт, когда они будут.

Когда агент работает в своей ветке — карточка «Ветка агента» (или «Pull request #N»): `ветка → основа`, сколько
коммитов, «Принять», «Открыть на GitHub», «Отклонить». «Изменения» показывают всё от основы, коммиты агента тоже.

## Устройство

- Правила — в `settings` (`git.rules:<проект>`), ветка агента и её основа — `git.branch:<проект>`.
  `GET /api/projects/:id/git`, `PUT …/git/rules`, `POST …/git/accept`, `POST …/git/reject` (`work/project-git.ts`).
- Ветку переключает Drimvox перед работой агента. Открытая ветка агента сохраняется: следующее сообщение идёт в неё.
- Коммитит Drimvox: агент вызывает `commit_changes` с сообщением, когда правила велят; в конце каждого хода всё
  незакоммиченное уходит одним коммитом (сообщение — последний сделанный пункт плана или просьба). Файлы с секретами
  (`.env*`, `*.pem`, `*.key`, ключи SSH) и папки зависимостей в коммит не попадают. Агенту сказано самому не
  запускать git commit/push/checkout.
- В конце хода, если включено и есть GitHub: ветка отправляется, pull request в основу открывается один раз.
- «Принять» — ветка вливается в основу здесь (`merge --no-ff`), основа отправляется на GitHub (pull request закрывается
  как влитый сам). «Отклонить» — назад на основу, ветка остаётся, pull request закрывается.
- Состояние «готово» пишется после коммита и отправки: до этого новое сообщение ждёт.

## Тесты

- Ядро: коммит по слову агента в своей ветке, `.env` не в коммите, правила в подсказке агенту; «Изменения» от основы;
  «Принять» вливает в main, «Отклонить» возвращает на main и оставляет ветку; «Не коммитит» — ничего не коммитит и
  инструмента нет.
- e2e: карточка с тремя списками и значениями по умолчанию, «Ветка агента → main», «Принять».
- Pull request на GitHub проверен только кодом: поддельный GitHub в тестах отдаёт репозиторий как файл, не по https.
