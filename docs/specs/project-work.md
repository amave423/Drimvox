# Спека: работа над пунктом — как Claude Code

## Зачем

Живой прогон «Лесопилки» (DeepSeek V4.1 Flash, 2026-10-18): первый пункт шёл 27 минут и 339 действий (файлы
читались 137 раз), второй — 35 минут. Проверяющий запускал свой Chrome скриптами и так и не вынес решения. Пункт
был выполнен наполовину. Файлы и адреса страниц — транслитом (`kalkulyator`, `korzina`). После «Принять» в папке
проекта не оказалось `node_modules`, и `npm run dev` не запускался. Пользователь просит: «пусть работает так же,
как ты, с теми же инструментами».

## Что остаётся

- Опрос и список задач (`docs/specs/backlog-loop.md`): круги вопросов, направление дизайна, MVP первым, выбор
  захода до 3 очков. Опрос пользователь назвал идеальным.

## Что меняется

1. **Пункт — это разговор в папке проекта.** «Начать» создаёт разговор (чат), привязанный к проекту и пункту,
   с подключённой папкой проекта. Первое сообщение — сам пункт: название, «готово, когда…», о проекте, бриф.
   Разговор живёт в проекте (на его странице и под ним в боковой панели), а не в общем списке чатов.
2. **Агент работает прямо в папке**, как в чате с папкой и как Claude Code: читает, правит, запускает команды.
   Копии проекта (worktree) и слияния нет. Опасные команды спрашивают разрешения в ответе.
3. **Точка отката на весь пункт.** Перед первым сообщением Artel снимает папку (`refs/artel/item/<id>`, как
   снимки чата с папкой). «Откатить пункт» возвращает папку к этому снимку; пункт снова в списке.
4. **Без проверяющего.** Агент сам проверяет работу: сборка и тесты проекта, запуск сервера разработки в фоне
   и взгляд на страницу (на компьютере и телефоне), каждый пункт «готово, когда…». Ответ кончается коротким
   отчётом: что сделано по каждому пункту и как запустить.
5. **Ревью человека.** Когда агент закончил ответ, пункт «ждёт проверки». Над полем ввода: что изменилось
   (файлы), «Принять» (один коммит в текущую ветку проекта с названием пункта) и «Откатить пункт». Можно просто
   написать, что не так, — агент продолжит в том же разговоре со всей историей, пункт снова «в работе».
6. **Дальше.** После «Принять» — следующий пункт захода: новый разговор.
7. **Модель по подписке.** Если выбрана Claude Code или Codex, пункт делает сама программа в папке проекта —
   тем же разговором, как в чате.

## Правила агента в пункте

- Имена файлов, папок, адресов страниц, переменных — по-английски (`calculator`, `/cart`), без транслита.
  Тексты на сайте — на языке пользователя.
- Проект должен запускаться: зависимости установлены (`npm install` и т. п.), `npm run dev` (или что принято)
  стартует без ошибок; агент проверяет это сам, запуская сервер в фоне.
- Делать пункт целиком: прежде чем закончить, пройти по каждому «готово, когда…».
- Дизайн — по брифу проекта, если он есть; смотреть на страницу, а не верить себе на слово.
- Фоновые процессы, запущенные в ответе, останавливаются в конце ответа (порт не остаётся занятым).

## Пределы и память

- До 200 шагов на ответ (в обычном чате с папкой — 40). Дошёл до предела — ответ кончается, «Продолжи» идёт
  дальше.
- Память как у агента (`agent/memory.ts`): при 60 % контекста старая часть ответа заменяется итогом.
- Скиллы проекта (`.artel/skills`, `.claude/skills`) и общие скиллы Artel — как у агента: список в системном
  тексте, `use_skill` открывает нужный. Так же и в обычном чате с папкой.

## Данные

- `chats.project_id`, `chats.item_id` — разговор пункта (новая миграция).
- `backlog.chat_id`, `backlog.checkpoint`; статус пункта получает значение `review`.
- Старые задачи пунктов (`tasks.kind = 'item'`) остаются читаемыми; новые не создаются.
