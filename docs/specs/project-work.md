# Спека: работа над проектом — дал задачу, агент делает

## Зачем

Список задач с очками, порядком, галочками и «↑↓ Убрать» пользователь назвал ужасным: «делаем как у тебя — дал
задачу, и агент делает её». Так работают Claude Code и DeepSeek Harness: одна долгая петля агента, свой чек-лист,
человек смотрит и вмешивается, когда хочет. Живой прогон (DeepSeek V4 Flash, «Заказ пиломатериалов») к тому же
повис на полчаса: агент ждал разрешения на команду вне папки, а карточку после возврата в чат не было видно.

Этот файл заменяет прежнюю спеку «пункт — разговор в папке» и выбор захода из `backlog-loop.md`. Опрос остаётся.

## Процесс

1. **Начало.** На странице проекта: что сделать (текст) и модели — кто проводит опрос, кто пишет план, кто
   работает, и «сильная модель» (необязательно), которая подключается, когда рабочая застряла. По умолчанию все
   три — последняя выбранная модель.
2. **Опрос** — как прежде (`quality.md`, `design.md`): круги по 3–4 вопроса с вариантами и пояснениями, свой
   ответ всегда можно вписать. Кнопка «Хватит» называется «Дальше решай сам»: агент додумывает остальное сам.
3. **План.** Модель плана пишет итоговый план: что строим (несколько предложений), шаги — короткий чек-лист
   (5–20 пунктов), страницы и что на каждой, технологии и решения с причинами, как проверить (команды,
   страницы), дизайн-бриф. Под планом: бюджет (в валюте из настроек) и
   время в часах, кнопка «Поехали» и поле «Поправить план» — правки уходят модели плана, она пишет план заново.
4. **Работа** — одна долгая петля агента в разговоре проекта (один разговор на проект, в нём вся история).
   Агент работает прямо в папке проекта, полностью сам: читает, пишет, запускает команды, ставит зависимости.
   Разрешения спрашивают только опасные команды (вне папки, удаление, сеть с отправкой — `agent/commands.ts`).
   - **Чек-лист** ведёт сам агент инструментом `update_checklist` (весь список с отметками); начальный — шаги
     плана. Справа от разговора: чек-лист с отметками, короткими пунктами. После 25 действий без
     `update_checklist` Drimvox напоминает отметить сделанное.
   - **Язык.** Агент пишет пользователю на его языке (языке плана): сообщения, чек-лист, вопросы, итог.
   - **Проверка** — его же работа: запускает проект и смотрит на страницы (`look_at_page`, компьютер и
     телефон), проходит сценарии как человек (`look_at_page` с шагами: нажать, ввести, подождать), пишет и
     запускает тесты. Не больше 8 взглядов за ответ, без бесконечной полировки.
   - **Вопросы** агент задаёт, но не ждёт (`ask_user`: вопрос и что он предполагает пока); вопрос виден
     справа, ответ — обычное сообщение в разговоре.
   - **Сообщения на ходу.** Пользователь пишет в разговор, пока агент работает: текущий шаг доделывается,
     сообщение встаёт в разговор, агент учитывает его и продолжает.
5. **Конец.** Агент вызывает `finish_work` с отчётом (что сделано, как запустить) и, если результат —
   сайт или сервер, с `start` (команда и адрес). Работа «готова», отчёт — отдельно, во вкладке «Запуск»; после
   него агент ничего не пишет. Drimvox сам запускает результат (`site:<проект>` в фоновых процессах): «Открыть»,
   «Остановить», «Запустить». Он работает, пока работает Drimvox (и в трее), и останавливается, когда агент снова
   берётся за проект. Принимать ничего не надо: всё уже в папке. Можно написать в разговор ещё.
6. **Пределы.** Бюджет и время задаются в плане и меняются прямо во время работы, без остановки. Кончились —
   агент останавливается и спрашивает «продолжать?»: прибавить и продолжить или закончить. Бесплатные и
   локальные модели бюджет не тратят.
7. **Застрял.** Модель закончила ответ без `finish_work` — Drimvox напоминает о незакрытых пунктах (до 3 раз
   подряд без продвижения по чек-листу). Не помогло — подключается сильная модель, если она задана; иначе
   работа встаёт с «застрял» и кнопкой «Продолжить».

## Рабочее место проекта

Разговор проекта — рабочее место с вкладками:

- **Работа** — разговор как в Claude Code: текст, свёрнутые действия между ним, скриншоты там, где сделаны;
- **План** — план целиком, только чтение (правки — сообщением агенту);
- **Изменения** — что поменялось в папке с последнего коммита, новые файлы тоже (`GET …/work/changes`, индекс
  git не трогается);
- **Запуск** — запущенный результат и итог агента.

Справа: состояние (работает / ждёт разрешения / готово / остановлено — бюджет, время, застрял, ошибка, «Стоп»),
запущенный результат с «Открыть», чек-лист, время, потрачено, число действий (бюджет и часы можно поменять),
вопросы агента. Отдельного журнала и полосы скриншотов нет: всё это в разговоре.

## Устройство

- Работа идёт в ядре, а не в запросе окна: окно может уйти и вернуться, закрыть разговор, открыть другой.
  Разговор опрашивает ядро, пока работа идёт, и видит открытые просьбы о разрешении.
- Одна петля держит контекст модели между ответами: сообщение пользователя закрывает текущий ответ, встаёт в
  разговор, и следующий ответ продолжает с тем же контекстом (память `agent/memory.ts` — при 60 % контекста).
- Модель по подписке (Claude Code, Codex) работает своей петлёй: Drimvox отдаёт ей план одним сообщением.
- git: Drimvox не включает его сам. Папка без git — страница спрашивает «Включить историю версий (git)?».
  Drimvox не коммитит работу агента: принимать ничего не надо, git остаётся пользователю.

## Данные

- Новая таблица `project_work`: модели (опрос, план, работа, сильная), разговор, бюджет и часы, чек-лист,
  вопросы, скриншоты, состояние и причина остановки, потраченное время, итог (`report`) и как запустить
  результат (`site_command`, `site_url`).
- План — в `project_plans` (как прежде), с полями `summary` и `steps`.
- Старый список задач (`backlog`) остаётся читаемым; новые задачи в него не попадают.

## Тесты

- Ядро: опрос → план с шагами → «Поехали» создаёт разговор проекта и чек-лист; петля с поддельной моделью:
  `update_checklist`, `ask_user`, `finish_work`; сообщение на ходу попадает в следующий ответ; бюджет кончился —
  остановка «budget», прибавили — продолжает; без `finish_work` — напоминание, затем сильная модель; правка плана;
  язык пользователя; напоминание о чек-листе; итог и запуск результата, «Стоп»/«Запустить»; изменения папки.
- e2e на окне: страница проекта без списка задач, модели на старте, план с «Поехали», панель справа с
  чек-листом, сообщение на ходу, вкладки План / Изменения / Запуск.
