# Правила проекта Drimvox

Для всех, кто пишет код в этом репозитории: людей и ИИ-агентов.

## Сначала прочитай
- `docs/CONTEXT.md` — что строим, для кого, этапы и уроки прошлого проекта (Orqen).
- `docs/DESIGN.md` — дизайн-система «Корректура»: токены, шрифты, тексты.
- `docs/specs/*.md` — как устроена каждая часть (проекты, чат с папкой, браузер агента, уведомления, MCP и скиллы, локальные модели, сервер). Меняешь поведение — обнови спеку в том же коммите.

## Устройство
```
packages/shared  схемы zod и типы, общие для ядра и интерфейса
packages/core    ядро: Hono API, SQLite (node:sqlite), раздача собранного UI
apps/web         интерфейс: React + Vite, говорит с ядром через типизированный клиент hono/client
apps/desktop     Electron: окно + ядро в utilityProcess + preload с токеном
apps/server      сервер для Linux: ядро + интерфейс для браузера, вход по паролю, systemd и Tailscale
```
Ядро одно для десктопа и серверного режима. Электрон-специфичное — только в `apps/desktop`, серверное — в `apps/server`.

## Команды
- `npm run dev` — интерфейс с горячей перезагрузкой, Electron перезапускается при правках main/preload/core.
- `npm start` — собрать и запустить как в проде.
- `npm run verify` — типы, юнит-тесты, сборка, e2e на настоящем окне. **Зелёный verify — единственное определение «готово».**

## Правила
1. Делаем то, о чём попросил владелец, или текущий этап из `docs/CONTEXT.md`. Фичи «по пути» не добавляем.
2. Сначала тест, потом код. Для ядра — vitest в `packages/*/test`, для поведения окна — Playwright в `apps/desktop/e2e`, для сервера в браузере — в `apps/server/e2e`.
3. Файл длиннее ~400 строк — разбей по ответственности.
4. Новые поля БД — только новой миграцией в `packages/core/src/db.ts`. Старые миграции не редактируем.
5. Все тексты интерфейса — через `apps/web/src/i18n.ts`, в обоих языках сразу.
6. Цвета — только токены из `tokens.css`. Новых hex в компонентах не появляется.
7. API ядра: вход по токену (десктоп) или по паролю с cookie-сессией (сервер), проверка Host. Без входа открыты только `/api/health` и `/api/auth/*`.
8. Секреты (ключи провайдеров) не попадают в git, логи и ответы API.
9. Коммиты: коротко, по-английски, описывают само изменение. Внутренние коды этапов (M1, M2…) в сообщения не пишем — посторонним они ничего не скажут.
