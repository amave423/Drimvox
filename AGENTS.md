# Правила проекта Drimvox

Для всех, кто пишет код в этом репозитории: людей и ИИ-агентов.

## Сначала прочитай
- `docs/CONTEXT.md` — что строим, для кого, как приложение выглядит сейчас и уроки прошлого проекта (Orqen).
- `docs/DESIGN.md` — дизайн-система «Корректура»: токены, шрифты, тексты.
- `docs/specs/*.md` — как устроена каждая часть. Меняешь поведение — обнови спеку в том же коммите. Главные:
  - `chats.md`, `chat-folder.md`, `chat-attachments.md` — чат, чат с папкой, вложения;
  - `project-work.md`, `project-git.md` — проекты: один разговор, проверяющий, ревьюер, заметки в `AGENTS.md`, git;
  - `providers.md`, `catalog.md`, `model-chains.md`, `cli-agents.md` — провайдеры, цены, цепочки бесплатных моделей,
    программы по подписке (Claude Code, Codex, Antigravity);
  - `local-models.md`, `local-images.md`, `local-audio.md`, `local-speech.md` — Ollama, stable-diffusion.cpp и
    ComfyUI, whisper.cpp, Piper;
  - `tools.md`, `agent-browser.md`, `web-search.md`, `ssh.md`, `github-publish.md` — инструменты агентов;
  - `media.md`, `media-director.md`, `notifications.md`, `server.md`, `macos.md`.

## Устройство
```
packages/shared  схемы zod и типы, общие для ядра и интерфейса
packages/core    ядро: Hono API, SQLite (node:sqlite), агенты, провайдеры, локальные движки, раздача собранного UI
apps/web         интерфейс: React + Vite, говорит с ядром через типизированный клиент hono/client
apps/desktop     Electron: окно + ядро в utilityProcess + preload с токеном; встроенный браузер агента
apps/server      сервер для Linux: ядро + интерфейс для браузера, вход по паролю, systemd и Tailscale
```
Ядро одно для десктопа и серверного режима. Электрон-специфичное — только в `apps/desktop`, серверное — в `apps/server`.
Данные приложения — в папке данных (`%APPDATA%\Drimvox` на Windows): база `drimvox.db`, вложения, скачанные модели,
заметки и состояние проектов (`projects/<имя>-<хеш>/`).

## Команды
- `npm run dev` — интерфейс с горячей перезагрузкой, Electron перезапускается при правках main/preload/core.
- `npm start` — собрать и запустить как в проде.
- `npm run verify` — типы, юнит-тесты, сборка, e2e на настоящем окне. **Зелёный verify — единственное определение «готово».**
  Идёт около шести минут; два verify сразу не запускай — они делят порты и папку сборки.
- `npm run screenshots` — заново снять картинки README (`apps/desktop/shots`, поддельный провайдер, пример — клиника).
- `npm run live-check` — проверка на настоящих провайдерах (нужны ключи; тратит деньги).
- `npm run release -- X.Y.Z` — поднять версию, закоммитить и поставить тег; потом `git push origin main` и
  `git push origin vX.Y.Z`, сборки делает GitHub Actions. Выпуск — только когда об этом попросил владелец.

## Правила
1. Делаем то, о чём попросил владелец. Фичи «по пути» не добавляем; замеченное по дороге — предложить, не делать.
2. Сначала тест, потом код. Для ядра — vitest в `packages/*/test`, для поведения окна — Playwright в `apps/desktop/e2e`,
   для сервера в браузере — в `apps/server/e2e`. Тест сначала должен упасть.
3. Файл длиннее ~400 строк — разбей по ответственности.
4. Новые поля БД — только новой миграцией в `packages/core/src/db.ts`. Старые миграции не редактируем.
5. Все тексты интерфейса — через `apps/web/src/i18n.ts`, в обоих языках сразу (`locales/ru.ts`, `locales/en.ts`).
6. Цвета — только токены из `tokens.css`. Новых hex в компонентах не появляется. Выпадающие списки — `ui/Dropdown.tsx`,
   не голый `<select>`.
7. Изменил интерфейс — посмотри на него: собери, сними экран и прочитай картинку. Зелёных тестов для интерфейса мало.
8. API ядра: вход по токену (десктоп) или по паролю с cookie-сессией (сервер), проверка Host. Без входа открыты только
   `/api/health` и `/api/auth/*`.
9. Секреты (ключи провайдеров, пароли) не попадают в git, логи, ответы API и заметки агентов.
10. Живые прогоны агентов — на копии данных (`DRIMVOX_USER_DATA` указывает на копию папки данных), а проект — на клоне,
    не в настоящей папке владельца.
11. Комментарий в коде объясняет «почему» и ссылается на то, что видели вживую («seen live: …»); пересказ кода не нужен.
12. Коммиты: коротко, по-английски, описывают само изменение. Внутренние коды этапов (M1, M2…) и подписи ИИ
    (Co-Authored-By) в сообщения не пишем.
